# Goal of This Example

This directory contains several TomoATT imaging examples for common local-earthquake tomography tasks:

1. Processing earthquake arrival-time data for seismic tomography.
2. Designing checkerboard tests to evaluate data resolution.
3. Performing real-data local-earthquake traveltime tomography and earthquake relocation.
4. Plotting and inspecting inversion results.

The data and workflow used in this example follow [Chen et al., 2026](https://doi.org/10.1038/s41561-025-01893-z). Chen, J., Xu, M., Bai, Y., Wu, S., Xiao, X., Hao, S., ... & Tong, P. (2026). High normal stress promoted supershear rupture during the 2023 Mw 7.8 Kahramanmaras earthquake. Nature Geoscience, 1-8.

This example is based on the GitHub repository [TomoATT_examples_for_course2026](https://github.com/JingChen-Thu/TomoATT_examples_for_course2026).

## Workflow

### Preparation: Install TomoATT and PyTomoATT

Create a new conda environment:

```bash
conda create -n tomoatt_conda
```

Activate the environment and install TomoATT and PyTomoATT:

```bash
conda activate tomoatt_conda
mamba install tomoatt pytomoatt
```

If `mamba` is not available, install it first with `conda install -c conda-forge mamba`, or install the packages directly with `conda install tomoatt pytomoatt`. Direct conda installation may take longer.

Test the TomoATT installation:

```bash
TOMOATT
```

If the following message is printed, TomoATT is installed correctly:

```bash
usage: mpirun -np 4 TOMOATT -i input_params.yaml
Error: input parameter file not found
```

Test the PyTomoATT installation:

```bash
pta -h
```

If the following message is printed, PyTomoATT is installed correctly:

```bash
usage: pta <command> [<args>]
...
```

### Step 1: Process Arrival-Time Data

Reliable arrival-time data are the foundation of a reliable inversion. Enter the data-processing directory:

```bash
cd Step1_Data_Process
```

This directory provides five processing notebooks. They keep reliable data inside the study region and remove data outside the study region or data that are relatively unreliable. Intermediate files generated by the notebooks are written to `output_data`, and figures are written to `figs`.

#### Preparation: Unpack the Data File

Unpack `traveltime_data/src_rec_Turkey.tar.gz` to obtain the original arrival-time file `traveltime_data/src_rec_Turkey.dat`:

```bash
cd traveltime_data
tar -xf src_rec_Turkey.tar.gz
cd ..
```

The file `traveltime_data/src_rec_Turkey.dat` follows the TomoATT source-receiver file format. The following notebooks filter this data set for tomography.

#### 1. Define the Study Region and Remove Events Outside It

Notebook and data file:

- `DataProc1_remove_data_outside_study_region.ipynb`
- `traveltime_data/src_rec_Turkey.dat`

This notebook defines the study region and removes earthquakes and stations outside the region. The study region can be rotated if needed. Output files include:

- Rotated-region data file: `output_data/step1_src_rec_indom.dat`
- Original-region earthquake list: `output_data/step1_ev_list.dat`
- Original-region station list: `output_data/step1_st_list.dat`
- Original-region data file: `output_data/step1_src_rec_data_norot.dat`

#### 2. Use Linear Regression to Remove Large-Residual Data

Notebook and data file:

- `DataProc2_keep_reliable_data_by_linear_regression.ipynb`
- `output_data/step1_src_rec_indom.dat`

This notebook plots distance versus first-arrival time and removes large-error arrival-time data using linear regression. Output files include:

- Filtered data file: `output_data/step2_src_rec_remove_outlier.dat`

#### 3. Remove Events with Too Few Arrival Times

Notebook and data file:

- `DataProc3_remove_events_with_few_arrivals.ipynb`
- `output_data/step2_src_rec_remove_outlier.dat`

This notebook removes events with fewer than a specified number of arrival times. When an event has too few arrivals, its source parameters are difficult to constrain accurately. Output files include:

- Filtered data file: `output_data/step3_src_rec_filtered.dat`

If you are confident in the source information, this step can be skipped.

#### 4. Generate Differential Arrival Times

Notebook and data file:

- `DataProc4_generate_differential_arrival_times.ipynb`
- `output_data/step3_src_rec_filtered.dat`

This notebook generates common-source or common-receiver differential arrival times from absolute arrival times according to selected filtering criteria. Output files include:

- Data file with common-source differential data: `output_data/step4_src_rec_cs.dat`

Common-source differential arrival times are insensitive to source uncertainty and can improve imaging reliability. Common-receiver differential arrival times are insensitive to structure near stations and can improve relative earthquake relocation as well as resolution near sources. Common-receiver differential data are more sensitive to source uncertainty, so source information should be as accurate as possible before using them.

After this step, the processed data are ready. Back up the processed data to `ENG/1_src_rec_files/src_rec_file.dat` for later inversions.

#### 5. Optional: Assign Weights to Events and Stations

Notebook and data file:

- `DataProc5_optional_set_data_weights.ipynb`
- `output_data/step4_src_rec_cs.dat`

This notebook assigns weights to earthquakes and stations. When data are distributed unevenly, weighting can accelerate convergence and reduce the number of iterations needed. Output files include:

- Weighted data file: `output_data/step5_src_rec_weight.dat`
- Earthquake weight file: `step5_ev_list_weight.dat`
- Station weight file: `step5_st_list_weight.dat`

This example workflow does not use data weights by default. Add them if needed for your own study.

#### 6. Finish Data Processing

Return to the main directory `PATH/ENG`:

```bash
cd ..
```

### Step 3: Invert for an Initial 1-D Model

The model built in Step 2 can be used by TomoATT, but it may not yet be suitable. Here, a suitable model means that the mean residual between synthetic and observed arrival times is close to 0, for example with an absolute mean residual smaller than 0.1 s.

Only when the mean residual is close to 0 is the overall model speed neither too high nor too low. Otherwise, later iterations may first compensate for the mean velocity bias, causing the recovered perturbation relative to the initial model to be dominantly positive or negative. Such an initial model may still produce useful results, but it increases the risk of converging to a local minimum.

Seismic tomography is an ill-posed problem and the inverse problem is usually non-unique. A suitable initial model helps the inversion converge toward a more realistic model. This step therefore aims to obtain an initial model whose mean arrival-time residual is close to 0.

Notes:

1. Both the velocity model and earthquake locations affect arrival-time residuals, and the two are coupled. In practice, we often choose which one to trust more. Here, we trust the source locations and update the initial model so that the residual mean approaches 0. If the initial model comes from a reliable regional model, you may instead trust the model and perform preliminary earthquake relocation to reduce the residual mean.
2. In some tests, inversion results were not strongly dependent on the initial model. Quite different initial models still produced consistent results. This usually requires high-quality and well-distributed earthquake data.

Run the 1-D velocity-model inversion:

```bash
bash Step3_bash_1d_model_inversion.sh
```

The inversion uses:

- Data file: `./1_src_rec_files/src_rec_file.dat`
- Model file: `./2_models/model_1d_crust1.0_N31_61_31.h5`
- Parameter file: `./3_input_params/input_params_step1_1D_inv.yaml`

The corresponding TomoATT command is:

```bash
mpirun -n ${Nproc} ${TomoATT_path} -i 3_input_params/input_params_step1_1D_inv.yaml
```

Results are stored in `OUTPUT_FILES/OUTPUT_FILES_step1_1D_inv`. Important outputs include:

The final model is also backed up to `2_models/model_1d_after_1d_inv.h5`.

Use `Plot1_plot_1d_model_inversion_results.ipynb` to plot the initial and final 1-D models. The figure is written to `figs/model_inv_1d.png`.

### Step 4: Run a Checkerboard Test

The checkerboard test evaluates the resolving power of the current earthquake data for velocity structure and azimuthal anisotropy.

#### 1. Build the Checkerboard Model

Enter the checkerboard-model directory:

```bash
cd Step4_ckb_model
```

Use `ModelProc2_generate_checkerboard_model.ipynb` to add positive and negative velocity anomalies and anisotropy anomalies to the 1-D model obtained from `OUTPUT_FILES/OUTPUT_FILES_step1_1D_inv/final_model.h5`.

The velocity anomaly size is 1 degree x 1 degree x 10 km, and the anisotropy anomaly size is 1.5 degrees x 1.5 degrees x 10 km. The corresponding inversion-grid spacing in the parameter files is 0.5 degrees x 0.5 degrees x 5 km for velocity and 0.75 degrees x 0.75 degrees x 5 km for anisotropy.

The inversion grid is one of the core settings in tomography and depends strongly on checkerboard-test results. A few notes:

1. Azimuthal anisotropy is usually harder to recover than velocity structure, so the optimal velocity resolution is often higher than the optimal anisotropy resolution. Therefore, velocity anomalies are designed to be smaller in this checkerboard test.
2. The best recoverable anomaly size is roughly twice the inversion-grid spacing. Two adjacent positive and negative anomaly blocks can be approximated by a sine function and controlled by five inversion-grid points: zero at `x = 0`, peak at `x = pi/2`, zero at `x = pi`, trough at `x = 3pi/2`, and zero at `x = 2pi`. Thus, the grid spacing is half of the anomaly size.
3. The ultimate resolution limit is controlled by the inversion-grid spacing. A finer grid can represent smaller anomalies, but sparse data cannot effectively constrain overly fine structures, which may introduce artifacts or spurious anomalies. In practice, several checkerboard tests with different anomaly sizes are usually needed.

The model file is written to `output_model/model_ckb_N31_61_31.h5` and backed up to `PATH/ENG/2_models/model_ckb_N31_61_31.h5`.

The checkerboard model figure is written to `figs/ModelProc2_ckb_model.png`.

Return to `PATH/ENG`:

```bash
cd ..
```

Run:

```bash
bash Step4_bash_checkerboard_test.sh
```

The checkerboard test includes three steps.

##### Step 1: Compute Synthetic Observations in the Checkerboard Model

This forward simulation uses:

- Data file: `1_src_rec_files/src_rec_file.dat`
- Model file: `2_models/model_ckb_N31_61_31.h5`
- Parameter file: `3_input_params/input_params_ckb_signal.yaml`

The corresponding TomoATT command is:

```bash

```

The synthetic observation file is:

- Checkerboard arrival times: `OUTPUT_FILES/OUTPUT_FILES_ckb_signal/src_rec_file_forward.dat`

##### Step 2: Add Gaussian Noise

Use the following Python script to add Gaussian noise:

The noisy data file is:

- Noisy data file: `OUTPUT_FILES/OUTPUT_FILES_ckb_signal/src_rec_file_forward_noisy.dat`

By default, zero-mean Gaussian noise with a standard deviation of 0.1 s is added to absolute arrival times. Differential arrival times are still generated by subtracting absolute arrival times. The default 0.1 s value represents a typical manual-picking uncertainty and can be adjusted as needed.

##### Step 3: Invert the Noisy Checkerboard Data

Starting from the anomaly-free initial model, invert the noisy data to recover the checkerboard anomalies. The inversion uses:

- Data file: `OUTPUT_FILES/OUTPUT_FILES_ckb_signal/src_rec_file_forward_noisy.dat`


- Final model file: `OUTPUT_FILES/OUTPUT_FILES_ckb_inv/final_model.h5`

Use `Plot2_plot_checkerboard_test_results.ipynb` to plot the checkerboard-test results.

### Step 5: Real-Data Inversion

After using checkerboard tests to choose a suitable inversion-grid setting, perform real-data tomography to invert for velocity structure and azimuthal anisotropy.

Run:

```bash
bash Step5_bash_real_data_inversion.sh
```

The real-data inversion includes two steps.

#### 1. Preliminary Earthquake Relocation

To reduce the influence of initial source errors on the imaging result, first update earthquake locations in the initial model. This inversion uses:

- Data file: `./1_src_rec_files/src_rec_file.dat`
- Model file: `OUTPUT_FILES/OUTPUT_FILES_step1_1D_inv/final_model.h5`
- Parameter file: `./3_input_params/input_params_step2_reloc.yaml`

The corresponding TomoATT command is:

```bash
mpirun -n ${Nproc} ${TomoATT_path} -i 3_input_params/input_params_step2_reloc.yaml
```

This step updates earthquake locations and origin times for 30 iterations. Results are stored in `OUTPUT_FILES/OUTPUT_FILES_step2_reloc`. Important outputs include:

- Objective-function history: `OUTPUT_FILES/OUTPUT_FILES_step2_reloc/objective_function.txt`
- Observed arrival-time data after relocation: `src_rec_file_reloc_0030_obs.dat`
- Synthetic arrival-time data after relocation: `src_rec_file_reloc_0030.dat`

Notes:

1. After relocation, the observed arrival-time file changes. The input observed data `./1_src_rec_files/src_rec_file.dat` and the relocated observed data `src_rec_file_reloc_0030_obs.dat` differ in earthquake locations, origin times, and station arrival times. The changes in source location and origin time are expected. Station arrival times change because the origin time changes. The picked absolute arrival time is fixed; if the origin time of an earthquake shifts earlier by `t` seconds, all arrival times for that earthquake increase by `t` seconds.
2. Therefore, later inversions should use the updated data file after relocation.

#### 2. Joint Inversion for Velocity, Anisotropy, and Source Parameters

Finally, jointly invert for velocity structure, azimuthal anisotropy, and source parameters. This inversion uses:

- Data file: `OUTPUT_FILES/OUTPUT_FILES_step2_reloc/src_rec_file_reloc_0030_obs.dat`
- Model file: `OUTPUT_FILES/OUTPUT_FILES_step1_1D_inv/final_model.h5`
- Parameter file: `./3_input_params/input_params_step3_inv_reloc.yaml`

The corresponding TomoATT command is:

```bash
mpirun -n ${Nproc} ${TomoATT_path} -i 3_input_params/input_params_step3_inv_reloc.yaml
```

This tutorial example runs only 10 iterations, so the recovered anomalies are limited. Results are stored in `OUTPUT_FILES/OUTPUT_FILES_step3_inv_reloc`. Important outputs include:

- Final model file: `OUTPUT_FILES/OUTPUT_FILES_step3_inv_reloc/final_model.h5`
- Objective-function history: `OUTPUT_FILES/OUTPUT_FILES_step3_inv_reloc/objective_function.txt`

For a more complete 100-iteration run, use `3_input_params/input_params_step3_inv_reloc_100iter.yaml`. Results will be stored in `OUTPUT_FILES/OUTPUT_FILES_step3_inv_reloc_100iter`.

For validation, the 100-iteration final model is provided at `PATH/ENG/benchmark_dataset/OUTPUT_FILES_step3_inv_reloc_100iter/final_model.h5`.

Use `Plot3_plot_real_data_inversion_results.ipynb` to plot the real-data tomography results.

Notes:

1. TomoATT updates parameters iteratively. At iteration `k`, it computes the gradients of the objective function with respect to velocity structure, azimuthal anisotropy, earthquake location, and origin time, then updates these parameters to obtain iteration `k + 1`. The full run uses 100 iterations.
2. Velocity and anisotropy are updated with the steepest-descent method by default. Their gradients are normalized, and the maximum update step is controlled at each iteration. The default initial step length corresponds to a 2% perturbation.
3. Earthquake relocation also uses steepest descent to update each source location and origin time. Its gradients are normalized and controlled by maximum update steps independent of the structural parameters. The default maximum update is `0.05 km / 0.05 km / 0.05 km / 0.008 s` per iteration.
4. After preliminary relocation, sources still need to be updated during structural inversion. The relocated sources are suitable for the layered model, but once the structure changes during inversion, the source parameters also need to change. Because the model update is small at each iteration, conservative source-update steps are used.
